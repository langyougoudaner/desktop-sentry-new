## 待办不可回归项

- 拖动功能必须存在，不能为了修 Bug 禁用卡片拖动。
- 圆圈既能点击完成／恢复，也能作为既有拖动交互的一部分；点击与拖动要用最小距离正确区分。
- 卡片拖到其他日期后，日期归属必须真实更新；拖到过去立即成为逾期，但仍可以再拖回今天或未来。
- 今天页可以显示历史逾期待办；其他日期页不能重复显示全局逾期区。
- 在今天页完成历史逾期待办时，卡片缩为橙色圆环并飞向它的真实归属日期；在任务自己的日期完成时不飞行。
- 输入框、卡片和页脚保持同一左右边界；列表可以滚动，但不显示或预留原生滚动条宽度。
- 卡片圆角、选中深蓝填充、原位蓝色边框和克制柔光不能被滚动遮罩横向裁切。
- 日期变化只允许日期标签翻页，不能让整张卡片翻转。
- 不能用永久 padding、负偏移、扩大十几像素的外圈或重复卡片，来掩盖布局和动画问题。
- 视觉通过真实隔离预览由用户确认；编译和测试通过不能代替手感验收。

## 本轮失败原因，禁止照搬

2.0.5 的待办大改把一次完成动作拆成：即时数据提交、合成源位置占位、额外覆盖卡片、卡片折叠、圆环飞行及多次几何回传。多个状态同时改变列表成员、行高和覆盖层位置，导致 SwiftUI 重排与动画互相竞争，表现为卡顿、下移、消失节奏异常和难以预测的卡片状态。

不要重新引入 `V5TaskLocalCompletion*`、`V5TaskCompletionSourceSlot*` 或同类双卡片／占位槽方案，除非先提供一个能证明其必要性的最小原型，并得到用户明确同意。

## 正确的工作方式

1. 先确认用户这次究竟调整选中、拖动、完成、恢复、日期标签还是列表进出场，不把它们打包重构。
2. 找到能复现该问题的最小测试或纯表现规则，先让检查失败。
3. 每次只改变一个动画主体或一个状态边界。
4. 使用固定隔离预览路径，不覆盖 `/Applications/DesktopSentry.app`，也不读取真实数据。
5. 预览页必须直接打开日历，不要打开 Skill 管理页。
6. 用户确认后才更新正式版；正式版必须使用新版本号和构建号，并先备份 APP 与完整数据目录。
