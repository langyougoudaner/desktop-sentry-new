## 2026-08-21 用户确认的 V2 决策

- 首个 V2 原型显示公历、农历和传统节日；不显示二十四节气。
- 工作台始终保持双栏：左侧完整月历，右侧任务区。右栏不得收起或隐藏，打开页面后无需额外进入管理模式。
- 右侧任务区保留“倒数日 / 待办”一级切换，两种能力均在同一页面内完成。
- 产品目标是同时满足“看日历”和“管理任务”，高频流程优先减少点击次数，不能为了界面看起来极简而把常用入口藏入二级页面。
- Apple 提醒事项暂不阻塞本地工作台；架构保留可选适配接口，但 V2 原型不请求权限、不读取或写入 Apple 提醒事项。
- 动效以正常 macOS App 的系统手感为基准：选中立即变色并有轻微弹动，打开时轻微放大并淡入，关闭时轻微缩小并淡出；不要求用户定义精确参数，也不加入夸张或装饰性动画。
- 旧 V1 日历面板的视觉语言未获用户认可，不得继承其整块深灰、厚重灰卡、满排筛选胶囊、分隔线关闭叉和角落小月历；V2 应以 Desktop Sentry 现有系统玻璃与蓝色反馈为底，并借鉴浮引的大日期、小农历、轻盈卡片与双栏秩序。
- 具体交互蓝图记录在 `docs/product/ideas/CALENDAR-TASK-WORKBENCH-V2-INTERACTION-BLUEPRINT.md`。

## 为什么重做方向

首轮规格把参考软件只当作“简洁气质”参考，并为了首版轻量化而删除了普通待办入口、日历与待办的直接联动、常规窗口行为和必要动效。结果虽然具备 Deadline 数据、筛选和通知骨架，却没有形成用户想要的日历工作台。

本轮不在旧界面上继续换颜色、调间距。参考软件应作为交互与信息架构基准：借鉴其双栏比例、明显的模式切换、就地新增、日期与列表联动、状态密度、窗口层级和反馈节奏；不复制其专有素材、品牌或代码。

## 新的产品模型

目标从“独立 Deadline 列表”改为“日历 + 待办 + 倒数的一体化工作台”：

- 左侧日历负责定位时间和显示每天的事项密度。
- 右侧在“倒数日”和“待办”之间直接切换。
- 普通待办继续允许没有日期；有需要时再为某个待办补日期、时间和一次性通知。
- 独立倒数日仍可存在，用于纪念日、发布日或不属于普通待办的目标日期。
- 现有待办不被强制迁移或补日期，但应能在“待办”页直接看见并继续管理。
- 菜单栏重点倒数与通知仍保留，但不再代表整个页面只能管理 Deadline。

## 必须达到的主要交互

### 1. 可发现的新增入口

- “待办”页顶部始终显示就地输入框：`添加待办，回车确认`，旁边有清楚的加号。
- “倒数日”页在相同视觉位置提供 `添加倒数日`。
- 点击某个日期后再新增，默认把该日期带入编辑流程；用户仍可清除日期，使其成为普通无日期待办。
- 新增不应先让用户猜测某个隐藏菜单，也不应把最常用动作放进每行的更多菜单。

### 2. 日期点击与窗口拖动严格分离

- 单击日期只选择日期、更新高亮和过滤右栏，绝不移动窗口。
- 窗口只能从明确的顶部标题 / 工具栏空白区拖动；日历格、列表、筛选器、输入框和按钮都不是拖动区域。
- 日期按下时立即有视觉反馈，选择状态以短促、可中断的系统动画过渡；减少动态效果开启时改为淡入淡出。

### 3. 符合 macOS 习惯的关闭方式

- 独立窗口优先使用左上角原生关闭按钮；不得把关闭叉放在两栏分隔线附近。
- 如果最终采用从菜单栏弹出的临时浮层，则点击外部和 `Esc` 均可关闭，并从菜单栏日历入口附近出现和收回。
- 只能选择一种清楚的窗口模型，不能同时混合独立窗口、Popover 和自定义关闭逻辑。

### 4. 日历与列表联动

- 左侧保留清楚的年月、上月 / 下月和“今天”入口；今天与选中日期是两个可区分状态。
- 日期格显示事项点位或数量；选中日期后右栏切换到当天事项，并提供明显的“全部”返回路径。
- 右栏条目直接显示完成勾选、标题、日期 / 时间、剩余状态和通知状态；次要操作收进每行菜单。
- 完成、插入、筛选和日期切换都应有轻量、连续、可打断的动效，不使用装饰性弹跳。

### 5. 页面层级对齐参考产品

- 日历是主要视觉区域，不缩成角落里的日期选择器。
- 待办 / 倒数切换是一级入口，新增是页面内始终可见的高频入口。
- 信息密度应允许用户一眼看见月份、今天、选中日期、3–6 条事项及其状态，不留下大面积无意义空白。
- 采用系统字体、SF Symbols 和单层系统材质；强调色用于今天、当前模式、选中日期和关键状态，不把整个窗口染成灰色。

## 动效与反馈基线

- 从菜单栏打开时，面板从日历图标附近以短促的缩放 + 淡入出现，关闭沿原路径返回。
- 按钮和日期在按下瞬间反馈，不等操作完成后才变色。
- 列表新增 / 完成使用约 0.3–0.4 秒、无装饰性反弹的系统弹簧或等价自然过渡，并允许用户立即继续操作。
- 筛选与日期切换保持空间连续性；内容变化使用轻微位移或交叉淡化，不能整页突变。
- 尊重减少动态效果、减少透明度和增强对比度。

## 原型方式

下一次不先接真实存储、通知和菜单栏状态。执行主线先用完全隔离的内存样例制作一个可点击原型，只验证以下五条完整路径：

1. 从菜单栏日历图标打开并关闭页面。
2. 在“待办”页直接输入并回车新增。
3. 点击某个日期，看到右栏联动，再新增该日期的待办。
4. 在“倒数日”页新增并设置通知时间。
5. 完成一项、切换筛选并观察列表反馈。

用户现场操作认可这五条路径后，才允许把原型连接到现有任务、Deadline 存储和通知；静态截图数量不能代替交互验收。

## 需要重新确认的关键范围

### 普通待办与日期

建议方向：现有普通待办继续原样显示；日期、时间和通知作为可选附加信息。没有日期的待办出现在“全部待办”，选中具体日期时不出现。这样既不强迫迁移，也不会把待办从日历页面里消失。

### 农历、节气和节假日

参考产品把农历、传统节日、节气和法定节假日整合在日期格中，但它们是三类不同数据：

- 农历可离线计算。
- 节气需要经过验证的本地算法或数据。
- 中国法定放假 / 调休逐年发布，需要年度维护或可选联网更新。

不能再默认全部排除，也不能在来源不可靠时假装准确；需要用户决定哪些进入下一版原型。

### 钉到桌面

仍作为后续阶段，不阻塞工作台本身；界面中暂不放不可用的假按钮。
