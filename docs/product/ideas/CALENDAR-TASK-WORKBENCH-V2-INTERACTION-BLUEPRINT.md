## 1. 目标

用户单击菜单栏日历入口后，立即同时获得两种价值：

1. 左侧直接查看完整月份、公历日期、农历和传统节日。
2. 右侧直接查看或管理倒数日与待办，不再进入第二个页面或额外展开任务区。

“交互简单”以完成高频任务所需的步骤衡量，不以删除入口、隐藏上下文或减少功能数量衡量。

## 2. 固定页面结构

### 左栏：月历

- 始终可见，不缩成角落里的日期选择器。
- 顶部提供上月、年月、下月和“今天”。
- 日期格主要显示公历日号，次级显示农历；传统节日使用克制、可读的强调标记。
- 不显示二十四节气。
- 今天和用户选中的日期必须是两种能同时识别的状态。
- 有待办或倒数日的日期显示点位或数量，但不把完整任务标题塞进日期格。

### 右栏：任务工作区

- 始终可见、不可收起，不存在“先展开右栏”这一步。
- 顶部是“倒数日 / 待办”一级切换，保持与参考产品相同的理解成本，但使用 Desktop Sentry 自己的视觉语言。
- 首次使用默认进入“待办”；以后记住用户上一次选择的右栏模式，重新打开时直接恢复，避免每次重复切换。
- 切换只更换右栏内容，左侧月历、当前月份与选中日期保持不动。
- 右栏宽度应能直接看清 3–6 条真实项目及关键状态，不留下大面积无意义空白。

## 3. 点击预算与高频流程

以下点击数从工作台已经打开后计算；键盘输入和按 Return 不算鼠标点击：

### 看日期

- 查看本月、农历和传统节日：0 次额外点击。
- 查看另一天对应的任务：单击该日期，共 1 次。
- 回到今天：单击“今天”，共 1 次。

### 新增普通待办

- “待办”模式顶部始终显示 `添加待办，回车确认` 输入区。
- 鼠标路径：单击输入区、输入、按 Return；共 1 次鼠标点击。
- 键盘路径：`Command-N` 或经真实原型验证后确定的单一快捷键直接聚焦输入区；不弹出多级编辑器。
- 当前选择了某个日期时，新待办预填该日期；用户可以在保存前或栏内编辑时清除日期，使其成为无日期待办。

### 新增倒数日

- “倒数日”模式顶部始终显示明确的 `添加倒数日` 入口。
- 单击入口后在右栏原位展开编辑，不打开与工作台失去空间联系的另一个大窗口。
- 标题和日期是第一层；时间、通知等低频字段在同一编辑卡内展开，不进入设置中心。

### 完成与编辑

- 单击行首完成圆圈即可完成，共 1 次；操作后提供短暂撤销入口。
- 单击标题进入栏内编辑，或使用经过原型验证、不会和单击选择冲突的标准方式；不要求先打开“更多”菜单。
- 每行的次要操作放在行尾更多菜单，主要操作不得全部藏入菜单。

### 排序

- 只有明确的拖动手柄可以排序任务。
- 拖动手柄、窗口拖动、日期选择和行内编辑使用互不重叠的命中区域。
- 拖动时项目跟随指针，插入位置实时反馈；没有抓住手柄时不得误排序。

## 4. 日期与任务联动

- 初次打开默认选择今天，右栏显示今天相关项目；“全部”是右栏内清楚可见的返回路径。
- 单击日期后，右栏立刻显示该日待办或倒数日；切换“倒数日 / 待办”时继续沿用该日期过滤。
- 用户从某日期开始新增，日期自动带入，减少重复选择。
- 无日期待办只出现在“全部待办”等合适范围，不伪装成今天任务。
- 日期选择只改变日期状态和右栏内容，绝不移动窗口。

## 5. 窗口与关闭行为

- 页面从菜单栏日历图标附近出现，让入口与结果保持空间联系。
- 禁止把整个内容背景设置为可拖动窗口区域。
- 若采用独立窗口，只允许从明确的顶部标题 / 工具栏空白区拖动，并提供 macOS 熟悉的左上角关闭方式。
- 若采用菜单栏浮层，单击菜单栏入口再次关闭，并支持 `Esc`；是否点击外部关闭由交互原型验证，不能造成填写到一半意外消失。
- 不得在两栏分隔线附近放一个孤立关闭叉。
- `Command-W` 必须能关闭当前工作台；关闭后再次打开应恢复合理的月份、模式和窗口位置，但不能恢复未确认的临时编辑内容造成误保存。

窗口采用独立窗口还是可保持编辑状态的菜单栏浮层，由执行主线在交互原型中提供一个推荐方案；规格只约束上述可预测行为，不锁死具体 AppKit 容器。

## 6. 动效与即时反馈

- 总体目标是正常、成熟的 macOS App 手感，与当前 macOS 系统面板、按钮和选择控件的反馈节奏接近；不追求独特动画风格，也不要求用户指定精确时间或弹簧参数。
- 打开从菜单栏入口附近轻微放大并淡入；关闭沿原路径轻微缩小并淡出。两条路径对称，不能突然出现或瞬间消失。
- 日期、模式切换、按钮和完成圆圈在按下时立即反馈；选中后使用系统强调色平滑过渡，并允许一次很轻的系统式弹动。
- 月份前后切换用方向一致的短促过渡；日期选择使用克制的高亮过渡。
- 新增项目从输入位置进入列表；完成项目先确认完成状态，再平滑进入完成区域，避免瞬间消失让用户怀疑误操作。
- 倒数日 / 待办切换只过渡右栏内容，不让整个窗口闪烁或重新布局。
- 优先使用 SwiftUI / AppKit 的系统动画语义与原生缓动；具体曲线、响应和弹性由执行主线在真实原型中微调，不另造一套与 macOS 明显不同的动画物理。
- 轻微弹动只用于按压、选中、插入和拖动落位等有直接因果的动作；禁止夸张回弹、持续晃动、循环动画、彩纸或为装饰而移动整个页面。
- 所有动画可被下一次操作打断；快速连续点击时不排队、不锁住界面。
- 减少动态效果开启时，缩放、位移和弹动改为短促交叉淡化，但保留颜色和状态反馈。
- 动效服务于因果、方向与状态理解，不能用长动画拖慢连续录入。

## 7. 数据与未来 Apple 提醒事项接口

### V2 本地工作台

- 现有普通待办继续是本地待办来源，不强制迁移或补日期。
- 日期、时间和通知作为普通待办的可选能力；没有日期仍能创建和管理。
- 独立倒数日保留自己的语义和存储，不伪装成普通待办。
- 本地工作台、倒数、农历、传统节日和本地通知在没有 Apple 权限时完整可用。

### 未来适配边界

- 预留一个抽象的任务来源 / 同步适配层，使本地任务与未来 Apple 提醒事项可以映射到统一的右栏展示模型。
- V2 原型和本地实现不得请求 Apple 提醒事项权限，也不得创建、读取、编辑或删除系统提醒事项。
- 未来接入时必须另行讨论权限时机、字段映射、双向同步、冲突处理、重复项与删除传播；当前不预设“最后修改时间获胜”等未经批准策略。
- 关闭或拒绝未来适配器时，本地工作台不降级、不丢数据。

## 8. 农历与传统节日

- 原型只展示农历日期与传统节日，不展示二十四节气。
- 农历与节日是可替换的数据提供层，不与任务存储绑死。
- 需要覆盖跨年、闰月和时区边界的样例；不能因为视觉正确就声称日期算法正确。
- “传统节日”不得冒充中国法定放假 / 调休安排；法定假日数据仍是以后单独讨论的模块。

## 9. 交互原型要求

执行主线下一步只能制作隔离数据的可点击原型，不连接真实用户数据、真实通知或 Apple 提醒事项。原型至少包含：

- 一个完整月份的公历、农历、传统节日和今天 / 选中日期状态；
- 3–6 条待办，覆盖无日期、今天、未来日期、已完成和可排序状态；
- 3–6 条倒数日，覆盖今天、未来、已到期和通知状态；
- 待办快速新增、栏内编辑、完成与撤销；
- 倒数日原位新增；
- 日期过滤、全部返回、模式切换和月份切换；
- 明确的窗口拖动区域和关闭路径；
- 上述操作对应的真实动效。

原型样例必须完全隔离，不读写真实 `data.json`、`deadlines.json` 或系统提醒事项。验收以现场操作或连续录屏为主，静态截图只能补充视觉细节。

## 10. 可观察验收标准

- 打开工作台后，月历和任务区同时完整可见，不需要额外展开或进入任务页面。
- 用户无需帮助说明即可找到待办快速输入和倒数日新增入口。
- 新增普通待办只需 1 次鼠标点击加输入和 Return；切换倒数日 / 待办只需 1 次点击。
- 单击任一日期只改变选择和右栏内容，窗口位置保持完全不变。
- 只有标题栏空白区能移动窗口，只有任务手柄能排序。
- 今天与选中日期同时存在时不会混淆；农历与传统节日可读但不压过公历日号。
- 无日期待办不会被错误归到今天；选择日期后新增会正确预填日期。
- 新增、完成、撤销、日期切换和模式切换都有即时、连贯且不拖慢操作的反馈。
- 打开、关闭、按压和选中的动态效果与正常 macOS App 接近：有轻微缩放、变色和必要的微弹动，但没有突兀跳变或夸张动画。
- `Esc`、`Command-W` 和可见关闭路径符合最终选定的窗口模型，不出现分隔线附近的孤立叉。
- 未授予任何 Apple 权限、无网络时，原型和后续本地工作台的核心流程仍成立。

## 11. 非目标

- 二十四节气。
- 中国法定放假和调休数据。
- Apple 提醒事项真实读取、写入或同步。
- iCloud 同步、系统 WidgetKit 小组件和跨设备同步。
- 钉到桌面；该能力继续保留为后续独立阶段。
- 在原型阶段写入真实用户数据、制造真实通知或迁移旧待办。
- 复制浮引或开源项目的品牌、专有素材、文案或代码。

## 12. 设计自由与禁止退化

执行主线可以根据真实原型调整具体尺寸、比例、间距、字体层级、图标选择、材质强度和动画实现，只要满足点击预算、固定双栏、可发现入口、手势隔离和验收标准。

不得用“首版轻量”作为理由删除高频入口、隐藏右栏、移除反馈或把完整任务流程降级成静态 Deadline 列表；也不得为了模仿参考产品而加入未经批准的同步、节气、小组件或桌面钉住。

旧 V1 原型的视觉已经被用户明确拒绝。V2 不得继承整块深灰背景、厚重灰卡、五个同级筛选胶囊、分隔线附近关闭叉、橙色粗描边和缩在角落里的小月历。视觉基底应延续 Desktop Sentry 现有搜索面板的系统玻璃、系统字体、轻边框、系统蓝强调和紧凑反馈；布局层级借鉴浮引日历的大公历、小农历、左大右小双栏比例、轻盈行卡和清楚顶部秩序。
