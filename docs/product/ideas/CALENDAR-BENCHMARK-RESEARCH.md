# 日历、待办与倒数产品研究

- Status: RESEARCH NOTE
- Owner: product discussion
- Created: 2026-08-21
- Related candidate: `docs/product/ideas/CALENDAR-TASK-WORKBENCH-V2.md`
- Execution: paused; this document is not an implementation order

## 结论先行

Desktop Sentry 不应把参考产品简化成“一个月历旁边放几条 Deadline”。更合适的组合是：

- 以浮引的日历看板作为产品与交互基准；
- 以 Calendr / Itsycal 验证原生菜单栏月历的窗口与日期浏览方式；
- 以 TodoPop / Reminders MenuBar 验证快速新增、栏内编辑、完成、排序和键盘操作；
- 以 LunarBar 验证农历、公共假日与极简菜单栏日历的本地实现边界；
- 仍使用 Desktop Sentry 自己统一的视觉语言与数据安全规则，不复制任何产品的品牌、专有素材或源代码。

这不是把多个界面拼在一起，而是让每个成熟产品回答一个问题，再由一个统一的信息架构承接。

## 1. 浮引 · FloGravity 4.8

来源：

- 官方更新日志：<https://fg.vkr.me/mac/changelog/>
- Mac App Store：<https://apps.apple.com/cn/app/id6783028258?mt=12>

官方 4.8.0 说明确认：

- 日历加入倒数日与待办区域；
- 支持展开 / 收起、分类筛选、快速添加与栏内编辑；
- 窗口会随看板状态调整；
- 倒数日支持公历、农历与重复规则，并汇总节假日和二十四节气；
- 待办支持分类、提醒时间、重复规则、完成推进与手动排序；
- 倒数日和待办可按范围、分类或指定项目钉到桌面，并有不同尺寸小组件；
- Apple 提醒事项同步是可选能力；未开启同步时仍能使用本地通知；
- 日历数据和格式做缓存，空闲时预热，但同步与提醒恢复避开主面板打开的关键路径。

### 应借鉴

- “倒数日 / 待办”是一级模式，不是藏在筛选器里的状态。
- 高频新增就在列表顶部，并允许栏内编辑。
- 日历、列表、桌面钉住和小组件共享同一批内容选择范围。
- 功能多但入口有层次：常用动作直达，复杂设置下沉。
- 窗口根据内容展开或收起，不长期留下大面积空白。
- 性能目标不是删掉功能，而是把缓存、同步和恢复移出打开面板的热路径。

### 不应照搬

- 浮引是多功能商业产品，不能复制其品牌、图标、文案、专有素材或代码。
- Desktop Sentry 当前不需要同步浮引的全部生态、账号、iCloud、小组件和 Pro 分层。
- 首个交互原型不接真实同步，也不钉住真实用户数据。

## 2. Calendr

仓库：<https://github.com/pakerwreah/Calendr>

- MIT 许可，原生 macOS 菜单栏日历；AppKit + SwiftUI，并包含事件、议程与提醒事项相关能力。
- 适合作为“菜单栏入口 → 月历 → 日期 → 议程”空间关系的参考。
- 日期支持 URL scheme 定位，说明日期选择可以成为清楚、可路由的状态，而不是临时视觉高亮。

### 应借鉴

- 菜单栏月历与议程并列的原生窗口行为。
- 日历选择状态与右侧内容的明确联动。
- 可选系统日历 / 提醒事项能力与本地界面解耦。

### 不应照搬

- 项目使用 RxSwift 等现有依赖；Desktop Sentry 不应为了参考界面整体引入其架构。

## 3. Itsycal

仓库：<https://github.com/sfsam/itsycal>

- MIT 许可，长期维护的轻量菜单栏月历；可显示系统日历事件，也可创建和删除事件。
- 证明“菜单栏月历 + 事件”本身可以保持小而原生。

### 应借鉴

- 从菜单栏即时打开的紧凑路径。
- 日历作为主要内容而不是角落日期选择器。
- 使用系统能力完成事件展示，不重新发明完整 Calendar。

## 4. LunarBar

仓库：<https://github.com/LunarBar-app/LunarBar>

- MIT 许可，中文语境的极简 macOS 状态栏日历；公开说明支持农历、公共假日、系统日历及提醒。

### 应借鉴

- 农历和公共假日可以作为可替换的数据提供层，不必与任务存储绑死。
- 中文日期格的层级与信息密度。
- 默认极简、扩展能力可选开启。

### 必须继续核验

- “公共假日”具体数据来源、更新机制和调休准确性；不能只看到界面就假设数据可直接复用。

## 5. Reminders MenuBar

仓库：<https://github.com/DamascenoRafael/reminders-menubar>

- GPL-3.0，SwiftUI 菜单栏提醒事项工具。
- 支持菜单栏内创建、搜索、筛选、完成和编辑提醒事项；快速新增支持自然语言日期、列表和标签；菜单栏可显示图标、计数或下一条提醒。

### 应借鉴

- 快速新增是主要入口，不要求先打开复杂编辑器。
- Apple 提醒事项是用户主动启用的来源，权限拒绝时应有清楚降级。
- 菜单栏展示可以在图标、计数与下一项之间提供明确优先级。

### 许可边界

- GPL-3.0 代码不得直接并入一个不准备按 GPL 发布的产品。当前只研究公开行为与信息架构，不复制代码。

## 6. TodoPop

仓库：<https://github.com/shakee93/todopop>

- MIT 许可，原生 SwiftUI 菜单栏待办工具。
- 支持回车快速新增、栏内改名、完成、跨日移动和历史；日期切换内容沿方向滑动。
- 拖动排序使用专用手柄，README 明确说明这样可以避免列表拖动吞掉输入框和其他手势。
- 预览目标用隔离的 seeded data 渲染，不污染真实数据。

### 应借鉴

- `回车新增`、栏内编辑和明确的键盘路径。
- 只有专用手柄可以拖动事项；输入框、日期和整行点击不承担拖动。
- 日期切换用有方向的连续动效，帮助用户理解前后日期关系。
- 可交互预览与真实存储分离。

## 7. Docket

仓库：<https://github.com/santoru/docket>

- 菜单栏任务工具，公开说明包括自然语言日期、可配置快捷键、一次快捷键打开、连续快捷键快速新增、通知和可选 Apple 提醒事项双向同步。

### 应借鉴

- 打开面板与直接进入新增是两个不同的快捷入口。
- 日期可以先用自然语言快速输入，再由完整编辑器补充细节。
- 系统提醒事项同步必须说明字段映射与冲突处理，不可假装无成本。

## 推荐的组合，不是拼贴

| Desktop Sentry 部分 | 主要参考 | 采用的原则 |
|---|---|---|
| 整体日历工作台 | 浮引 | 日历 + 倒数日 / 待办双模式、快速新增、栏内编辑、内容自适应 |
| 菜单栏打开与月历骨架 | Calendr、Itsycal | 原生锚定、日期选择与议程联动、保持轻量 |
| 中文日期信息 | LunarBar、浮引 | 农历 / 节日作为独立数据层，层级清楚 |
| 待办新增与编辑 | TodoPop、Reminders MenuBar | 回车新增、栏内编辑、明显完成入口、键盘可达 |
| 排序与手势 | TodoPop | 专用拖动手柄，内容区不拖窗口、不抢输入 |
| 倒数与桌面提醒 | 浮引 | 重点倒数、范围选择、后续钉住；首个原型先不落真实数据 |
| 系统提醒事项 | Reminders MenuBar、Docket | 用户主动启用、明确权限、字段映射与冲突策略 |

## 视觉参考优先级补充（2026-08-21）

“研究过”不等于“适合当视觉母版”。为避免再次把多个开源项目的局部界面生硬拼成一个面板，V2 的视觉参考按职责分层：

1. **整体构图与完整感：浮引。** 继续以其左大右小双栏、大公历、小农历、传统节日标签、清楚顶栏和浅层任务行为主要产品参考。
2. **左侧月历的第二视觉参考：LunarBar。** 借鉴它在紧凑菜单栏浮层中处理公历、农历、选中框、事件点位和系统材质的方法；不照搬它的整块深色外观、书签图标和多色点阵。
3. **窗口与原生克制感：Itsycal / Calendr。** 参考锚定菜单栏、月切换、日期选择、议程联动、浅色 / 深色适配和键盘路径；两者整体更偏工具型，不作为 V2 的主要审美模板。
4. **右侧任务微交互：TodoPop。** 参考回车新增、栏内编辑、专用排序手柄、完成动画和方向一致的日期切换；不复制其单栏信息架构和外观。
5. **产品归属：Desktop Sentry 现有 SearchPanel。** 字体、系统蓝、单层原生材质、轻顶光边框、圆角和 hover / press 反馈必须由 Desktop Sentry 自己统一，不能因为参考竞品而看起来像另一个独立 App。

执行时不得把不同参考产品各自的按钮、卡片、图标和颜色直接“缝合”。同一控件只允许有一个视觉来源；出现冲突时，优先级为 Desktop Sentry 产品归属与 macOS 熟悉行为 > 浮引整体层级 > LunarBar 月历细节 > TodoPop 微交互。

## 对 V2 的直接修正

1. 页面一级入口固定为“倒数日 / 待办”，而不是“即将到来 / 已到期 / 已完成 / 已归档”五个同级筛选按钮。
2. 待办顶部固定快速输入；倒数日顶部固定添加入口。复杂字段在展开编辑中完成。
3. 日历格只负责日期选择；窗口拖动只允许标题栏，事项排序只允许手柄。三类手势绝不共用区域。
4. 普通待办允许没有日期；选择日期后新增才预填日期。日期不是所有待办的门槛。
5. 右侧列表支持栏内完成、编辑和排序；更多动作下沉，不把常用动作全藏在菜单里。
6. 窗口应随右栏展开 / 收起调整，或提供与浮引相似的两种稳定布局；不能固定大窗后留下空白。
7. 农历和传统节日进入交互原型；法定放假 / 调休在核验可靠数据源后再承诺。
8. 原型必须能操作并展示过渡，不再用三张静态截图证明“设计完成”。

## 仍需用户决定

- 首个 V2 原型是否同时展示“农历 + 传统节日 + 二十四节气”，还是先只做农历与传统节日。
- “倒数日 / 待办”右栏是像浮引一样可收起，还是始终保留双栏；建议支持收起，因为它同时解决纯看日历和管理任务两种场景。
- Apple 提醒事项双向同步是否进入后续阶段；建议不阻塞本地工作台，但在架构上保留可选适配层。

## 2026-08-21 决策结果

- 农历进入首个 V2 原型，传统节日进入首个 V2 原型，二十四节气不进入。
- 工作台始终保持左月历、右任务区的双栏结构，右栏不收起。
- 右栏保留倒数日与待办两种一级模式，打开工作台后即可查看和操作，不增加进入管理页的额外步骤。
- Apple 提醒事项同步延期；本地工作台独立完成，架构仅保留未来适配接口。

## 研究边界

- 本轮只读搜索，没有克隆、安装或运行任何竞品。
- 没有修改 Desktop Sentry 应用代码，没有恢复执行主线。
- 开源许可允许研究公开行为，不等于允许随意复制实现；若未来需要参考具体代码，必须逐项目核对许可证和必要署名。
