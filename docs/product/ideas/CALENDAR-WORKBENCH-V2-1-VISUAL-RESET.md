## Why the current result failed

这不是在正确骨架上“再润色一下”就能解决的问题。当前实现直接违反了用户已经确认的核心体验：

- 使用标准黑色标题栏，同时在内容里再次绘制“日历任务工作台”头部，形成突兀的双标题结构。
- 左栏被限制为 430–470pt，右栏至少 470pt 且可无限扩张，实际权重与“左大右小”相反。
- 窗口最小高度 650pt，空状态又占满剩余高度，使右下角形成巨大无意义空白。
- 月历日期格只有 56pt 高，日号约 17pt；在大窗口中显得像被放在角落的小控件，而不是视觉主角。
- 左下“菜单栏重点”卡片与当前看日历 / 管任务主流程无关，挤压月历并制造额外层级。
- 倒数日名称、日期、提醒开关、时间和添加按钮被塞进一行；日期 / 时间使用系统紧凑控件但没有为中文本地化留足宽度，发生深色块与文字裁切。
- 添加按钮仅因名称为空而直接禁用，却没有“名称必填”标签、即时错误或把焦点送到缺失字段；用户完整填写日期和时间后仍无法理解为何不能提交。
- 预览可强制深色外观，但视觉证据没有避免把测试外观当成默认结果展示给用户，造成整块灰底、白字和黑色控件的不一致。

## Proposed reset

不再继续修补当前视图。V2.1 以“LunarBar 高保真月历视觉 + 浮引双栏工作台结构 + Desktop Sentry/macOS 统一外壳”为单一方向。

这里的“高保真”指月历的可观察视觉效果与比例，不指复制品牌：

- 对齐 LunarBar 的大日号 / 小农历层级、日期格密度、今天与选中状态、克制事件点位、系统材质和紧凑圆角。
- 不复制 LunarBar 名称、图标、书签符号、截图素材或品牌标识。
- LunarBar 是单栏产品，不能原样提供用户已确认的右侧倒数日 / 待办；右栏使用同一套字体、材质、间距、圆角和状态色自然延展，而不是换一套卡片设计。

## Hard visual rules

### Window and shell

- 去掉标准黑色标题栏和内容区重复总标题；整个工作台只有一层连续的系统材质。
- 采用菜单栏锚定的无独立标题栏浮层，或真正透明且与内容融为一体的全尺寸标题区；两者只选一种。
- 默认跟随系统外观，禁止把强制深色测试参数作为用户默认预览。
- 浅色必须是清晰的浅色系统材质与深色正文；深色必须是系统深色材质与足够对比度正文。禁止灰底上继续使用灰白层级。
- 窗口建议从约 900–980 × 560–620pt 起步，按真实内容调整，不再用 1040 × 700pt 的空壳证明“双栏”。

### Column balance

- 左侧月历占可用内容宽度约 60–64%，右侧任务区约 36–40%。
- 月历日号是左栏视觉主角，日期格随窗口高度充分展开；不得以 17pt 小数字漂在大片空白中。
- 移除左下“菜单栏重点”卡片。菜单栏剩余天数是菜单栏职责，不占月历主画面。
- 右栏列表和编辑器从顶端连续排布；空状态靠近新增入口，不能居中漂在整块空白里。

### Calendar fidelity

- 大公历、小农历；传统节日使用克制语义色，不显示二十四节气。
- 今天使用描边或次级状态，选中使用系统强调色实心状态；两者重合时仍可辨认。
- 有项目的日期只显示少量统一点位 / 数量，不用多色彩珠和无关书签图标。
- 顶部月份、左右切换和今天形成一个紧凑控制组，不再额外显示“日历”大标题占空间。

### Task side

- 右栏顶部保留一个系统式“倒数日 / 待办”分段控制；新增入口紧随其下。
- 列表使用轻量行与留白，不使用整排厚灰砖，也不让空状态占满整栏。
- 选中日期无项目时，显示一行短说明和明显的“为 8 月 28 日添加”入口；仍能一键返回全部。

### Countdown composer

- 新增倒数日改为右栏内的纵向小表单，至少分为“名称”和“日期 / 提醒”两行，不再把所有控件挤在一行。
- 名称明确标注“名称（必填）”，打开后自动聚焦。
- 提交按钮保持可点击；若名称为空，点击或 Return 后在名称下方即时显示“请输入倒数日名称”并保持用户已选日期和时间。
- 日期、时间使用足够宽度的本地化系统控件；任何语言和外观下不得裁切。
- 提醒关闭时隐藏时间；打开后显示“提醒时间”标签与完整时间控件。
- 添加成功后立即出现新行并给出短促反馈；失败时不清空任何已填字段。

## Acceptance proof before more implementation

新的执行规格必须先要求：

1. 一张默认系统浅色主界面截图；
2. 一张系统深色主界面截图；
3. 一张倒数日编辑状态截图，名称、日期、提醒时间均完整可见；
4. 一段从打开面板到成功新增倒数日的连续录屏；
5. 一段“名称为空”时出现即时错误、已选日期和时间不丢失的录屏；
6. 与 LunarBar 月历截图并排说明日号、农历、选中、点位、材质和比例是否达到高保真；
7. 用户亲自确认视觉与新增流程后，才允许继续接其他交互或真实数据。

构建成功、测试通过和执行线自评均不能代替以上视觉验收。

## Decision result

用户已明确同意“LunarBar 高保真月历视觉，但保留固定双栏；右侧倒数日 / 待办使用同一套视觉语言延展”，并补充批准日期悬停预选、点击选中、今日圆形标记以及今日选中后使用实心点保留身份的状态与动效。
