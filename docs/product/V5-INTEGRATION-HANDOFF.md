## 用户真正想保留的东西

### 1. 第五代的干净感

第五代的清爽视觉、大月历、左右分区和整体克制感是出发点，但不是像素级模板，也不是不能调整的旧代码。可以为了更自然的体验改布局、重构组件、调整层级和交互，只要最终仍然是一款干净、轻巧、像原生 macOS 工具的桌面软件。

### 2. 只做待办，不再做倒数日

新工作台只保留“待办”。待办本身可以选择日期，已经能覆盖用户原本使用倒数日的大部分目的。

- 不再给新界面增加“待办／倒数日”切换；
- 不继续扩展倒数日的新增、重复、颜色、删除等功能；
- 历史倒数日代码和资料先留在原处，不需要删除，也不要让它影响当前界面。

### 3. 恢复已经证明有价值的核心体验

- 鼠标悬停菜单栏图标时能快速看到日历；
- 只是悬停查看时，移开后自然收起；用户点击并开始操作后，窗口保持可用，直到点击外部或按 `Esc`；
- 左侧是信息完整、状态清楚的大月历，相邻月份日期可见并可选；
- 今天、选中日期、节日、农历和已有休／班信息能够同时正确表达，不互相覆盖；
- 右侧可以快速新增待办，默认使用当前选中的日期；
- 待办支持修改日期、填写简短描述、完成和恢复；
- 提醒由用户主动选择，选择日期不等于自动创建提醒；
- 月历日期与待办日期之间有自然、容易理解的联动。

这些是用户要得到的结果，不代表必须沿用第四代的页面结构或某一种状态管理方式。请复用真正可靠的逻辑，重新整理不可靠的部分。

## 新的液态动效参考

参考项目：

<https://github.com/Jakubantalik/Libraries/tree/main/packages/liquid-gooey>

用户喜欢其中液态合并、形变和移动拖尾所带来的生命感，希望桌面哨兵也能拥有这种更精致的反馈，但用户不预先指定它应该出现在哪里，也不要求为了“用上动效”而强行使用。

请你自行完成以下判断并落实到成品：

1. 先理解参考项目的视觉原理、交互用途和性能方式；
2. 判断桌面哨兵里哪些状态变化值得使用类似效果，哪些地方保持普通原生动画反而更好；
3. 决定使用一种、几种或不使用某个具体效果，并自行确定强度、节奏和出现位置；
4. 让动效帮助用户理解“选中了什么、什么内容展开了、任务发生了什么变化”，同时保持文字、日期和点击区域清晰；
5. 在“减少动态效果”开启时提供安静、直接的替代反馈。

这个 GitHub 项目是 React/SVG 实现，桌面哨兵是原生 macOS 应用。不要为了照搬而改变应用技术栈。你可以研究它的分层与形变思路后用 SwiftUI/AppKit 原生实现，也可以只吸收设计语言；如果确实复用其源码，应遵守项目的 MIT 许可并保留必要声明。

可供思考的场景包括日期选择的移动、快速新增入口到编辑卡片的形变、待办展开／完成反馈，以及菜单栏小入口到工作台的空间联系。这些只是灵感，不是指定答案。最终使用在哪里、是否使用，由你根据真实运行效果决定。
