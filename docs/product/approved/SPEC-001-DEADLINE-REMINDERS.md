## Problem and desired outcome

> 2026-08-21 产品复盘：首轮实现把参考产品降格为视觉气质参考，并把普通待办与 Deadline 强制拆开，造成入口、交互模型、窗口行为和整体完成度偏离用户原意。当前实现只保留为可回溯原型，不代表用户验收，也不得继续据此做增量视觉修补。

Desktop Sentry 当前可以管理本地待办、提示词和 Skill，但没有明确日期的 Deadline、倒数显示或到时提醒。用户希望继续保持左键复制提示词和右键原生菜单，同时在菜单栏右侧增加一个日历图标，打开一个简洁的月历 + Deadline 双栏面板。

第一版应允许创建多个独立 Deadline，在菜单栏持续展示一个重点项目的剩余天数，并为每个开启通知的项目在指定时间显示 macOS 弹窗和系统声音。它必须保持轻量、本地优先，不迁移现有待办，也不成为完整 Calendar 替代品。

## Evidence and assumptions

- 当前 `TaskItem` 没有计划日期或截止时间；用户明确不要求给旧待办补日期，也不要求迁移旧待办。
- 当前状态栏由一个标准 `NSStatusItem` / `NSStatusBarButton` 管理，左键复制、右键打开原生菜单。
- 当前提示词标题允许 10–25 字，并可能同时显示普通待办计数；Deadline 倒数与日历图标加入后需要明确显示优先级。
- 当前项目已有 SwiftUI、`NSPanel`、本地原子 JSON 存储和用户设置基础。
- 当前安装包只读测量约 2.4 MB；本功能的主要风险不是磁盘体积，而是状态栏命中、通知生命周期、用户数据安全和窗口行为。
- macOS 本地通知由 `UserNotifications` 提供，不要求 EventKit 或读取系统日历。
- 系统专注模式、勿扰模式和用户通知设置对弹窗与声音具有最终控制权，应用不能保证绕过系统设置发声。
- 单个标准状态栏按钮内按点击位置分发文字区和图标区在技术上可行，但必须在真实 macOS 26 菜单栏、复制视图、多显示器和刘海屏上验证；静态设计不是运行证据。

如果真实系统证明单个标准按钮无法稳定提供两个命中区，不能继续使用一个原生状态栏项目且保持右键菜单，批准的安全降级是：文字左键继续复制，Deadline 从右键菜单的显式入口打开。不得静默创建两个可被用户拖散的状态栏项目，也不得采用已弃用的 `NSStatusItem.view` 自绘方案。

## Options considered

### Approved smallest viable option

独立的本地 Deadline 模块、中等尺寸双栏面板、一个菜单栏重点倒数、每项一次性本地通知。它不读取系统日历，不联网，不修改现有普通待办。

### Smaller alternative

只在右键菜单增加 Deadline 列表，不提供月历面板和菜单栏倒数。实现更小，但不能满足持续查看剩余天数和参考界面的核心体验。

### Larger alternatives

- 钉到桌面的浮动小框。
- Apple Calendar / Reminders 读取与写入。
- 农历、节气、法定节假日及年度调休。
- 重复提醒、稍后提醒、位置提醒和完整日程中心。

这些能力会增加窗口、授权、同步或年度数据维护成本，首版不实施。

### Doing nothing

继续依赖 macOS 通知中心小组件。没有开发风险，但不能展示 Desktop Sentry 自己的 Deadline，也不能与现有菜单栏工作流结合。

## Approved scope

### 1. 独立 Deadline 数据

新增独立的 Deadline 领域，不修改 `TaskItem`，不为现有待办补日期。每项至少包含：

- 稳定唯一标识；
- 标题；
- 目标本地日期；
- 可选的明确时间；
- 通知是否开启；
- 进行中、已完成或已归档状态；
- 创建与更新时间。

标题和目标日期必填。通知关闭时具体时间可以为空；通知开启时必须由用户明确选择时间，界面不得自动使用午夜、早上 9 点或其他隐式默认值。

Deadline 模块数据应使用独立、原子保存的本地文件，例如应用数据目录下的 `deadlines.json`，而不是把唯一副本塞入旧版会重写的主 `data.json`。旧应用运行和保存时不得删除 Deadline 文件。文件缺失时视为空集合；损坏时应保留可恢复副本并安全回退，行为不得影响任务、提示词、Skill 或其他设置。

不自动永久删除 Deadline。归档项目保留在“已归档”中；永久删除只能由用户主动触发，并在明确确认后执行。

### 2. 剩余天数与重点项

- 按当前系统时区的自然日计算，不按秒或 24 小时连续刷新。
- 目标日期是今天时显示 `今天`；未来显示 `N天`；过去显示 `已到期N天`。
- 菜单栏一次只显示一个重点 Deadline；完整标题在面板和右键菜单中查看。
- 用户可手动选择任意进行中 Deadline 为重点项。
- 重点项完成或归档后，自动切换到目标时间最近的下一项；没有进行中项目时隐藏 Deadline 倒数。
- 切换重点项、自动接续或隐藏倒数不得改变其他 Deadline 的通知安排。
- 状态在创建、编辑、完成、归档、切换重点项和跨过午夜时更新；不得每秒轮询。

### 3. 菜单栏交互

继续使用一个标准原生状态栏项目：

- 左侧文字区域左键单击：复制当前常驻提示词，保持现有行为。
- 右侧日历 / Deadline 图标左键单击：打开 Deadline 面板。
- 任意区域右键：继续打开现有原生右键菜单。
- 右键菜单增加“打开 Deadline / 倒数日…”备用入口。
- 日历图标视觉保持克制，实际命中区域约 22pt，并有立即可见的按下反馈。
- 复制成功反馈只改变文字状态，不应让日历入口消失或失效。

菜单栏显示优先级为：Deadline 倒数与日历入口最高，常驻提示词其次，普通待办计数最低。空间不足时先省略普通待办计数，再缩短提示词；不得截断到无法看懂 Deadline 状态，也不得隐藏日历入口。

必须验证 VoiceOver、键盘备用路径、菜单栏空间不足、多显示器、刘海屏和 macOS 26 状态栏复制视图。日历图标不是唯一入口。

### 4. Deadline 双栏面板

新增中等尺寸、可拖动、可关闭的独立面板，不进入庞大的偏好设置页面。建议默认约 `820 × 560 pt`，允许合理缩放并记住最后位置与尺寸；具体数值可在视觉检查中小幅调整，不构成产品范围变化。

页面使用参考截图的简洁气质，但不逐像素复制专有设计：系统字体、SF Symbols、原生玻璃材质、柔和圆角、克制阴影、有限系统强调色，并适配浅色、深色、增强对比度、减少透明度和减少动态效果。

页面结构：

- 左栏为公历月视图；顶部提供上个月、今天、下个月。
- 日期格突出今天，并用简洁圆点或数量表示当天存在 Deadline；不把完整标题塞进日期格。
- 点击日期后，右栏只显示当天项目；“全部”恢复完整列表。
- 右栏提供“即将到来、已到期、已完成、已归档”视图。
- 即将到来按目标时间从近到远；已到期项目按逾期程度排序；已完成和已归档保持可理解的最近操作顺序。
- 顶部提供“添加 Deadline”。不显示不断跳动的秒钟。
- 每行显示标题、目标日期、可选时间、剩余/逾期状态、通知状态和重点状态。
- 每项支持设为重点、编辑、标记完成和归档；已归档项目支持恢复与经确认的永久删除。

首版不显示尚未实现的“钉到桌面”假按钮。面板首次尽量从日历图标附近出现；如果尺寸无法合理锚定，则在当前屏幕居中，之后尊重用户保存的位置。

### 5. 一次性本地通知

- 每个 Deadline 可独立开启或关闭通知；未显示在菜单栏中的项目也要正常通知。
- 第一次主动为某项开启通知时才请求系统通知权限，不在应用首次启动时请求。
- 开启通知但没有选择具体时间时不能保存为已安排状态，界面就地提示选择时间。
- 使用 macOS 标准弹窗和系统通知声音；首版不选择专属铃声。
- 到达目标日期与时间时只通知一次，不自动重复、不连续催促、不提供稍后提醒。
- 点击通知打开 Deadline 面板并定位对应项目。
- 应用在前台时也要按授权状态请求弹窗与声音呈现，不得因为正在运行而静默吞掉提醒。
- 编辑目标时间或通知开关时，应取消旧请求并正确重排；完成、归档或永久删除时取消尚未触发的请求。
- 用户拒绝权限、随后关闭权限或关闭声音时，Deadline 和菜单栏倒数继续工作，并显示真实通知状态，不伪称提醒已经启用。
- 通知标识必须稳定、可追踪和可撤销，避免产生孤儿通知。

### 6. 用户已确认的首版字段与操作边界

- 不增加备注、标签、分类和重复规则。
- 不增加自动提醒时间。
- 不增加稍后提醒、自动重复或位置提醒。
- 不自动永久删除归档内容。

## Non-goals

- 不读取、写入或同步 Apple Calendar / Reminders。
- 不联网，不访问对话历史，不加入第三方服务。
- 不提供农历、节气、法定节假日、调休或在线年度数据。
- 不做钉到桌面、始终置顶、系统 WidgetKit 小组件或桌面背景层窗口。
- 不修改、迁移或自动关联现有普通待办。
- 不做重复 Deadline、通知重复、连续催促、稍后提醒、位置提醒或强制突破专注模式。
- 不加入备注、标签、分类、主题皮肤或完整日程编辑器。
- 不改变文字区域左键复制、任意区域右键菜单和现有提示词 / Skill 核心能力。
- 不创建第二个可独立移动的状态栏项目，不使用已弃用的状态栏自绘入口。
- 不在本规格中安装到 `/Applications`、改变登录项、发布、升级版本号或创建远程仓库。

## Affected modules and invariants

预计涉及：

- `Sources/Models/`：独立 Deadline 模型与安全解码。
- `Sources/Store/`：Deadline 状态、排序、重点接续和独立原子存储。
- `Sources/Services/`：自然日计算与 `UserNotifications` 调度 / 取消。
- `Sources/App/AppCoordinator.swift`：新 store、面板和通知点击路由。
- `Sources/StatusBar/StatusBarController.swift`：尾随图标、点击分区、倒数标题和右键备用入口。
- `Sources/Panel/PanelFactory.swift`：仅在现有工厂无法表达新面板时做小范围扩展。
- 新的独立 Deadline SwiftUI 视图；不得继续把大量界面堆入 `SettingsView.swift`。
- `Info.plist`：仅加入通知实际需要且经验证的声明；不得加入日历或提醒事项用途说明。
- `build.sh`：任何新增生产 Swift 文件必须加入显式 `SOURCES=(...)`。
- `Tests/`：模型、存储、倒数、重点接续、标题组合与通知计划逻辑。

必须保持：

- 旧主 `data.json`、任务、提示词、Skill、复制历史和设置原样兼容。
- 本地原子保存和损坏数据保留策略。
- 左键文字复制、右键原生菜单、无网络和本地优先边界。
- 未授权通知时应用仍能完整使用 Deadline。
- 构建与部署分离，不覆盖 `/Applications/DesktopSentry.app`。

## Acceptance criteria

### Data and calculations

- 旧数据在没有 Deadline 文件时无损加载；任务、提示词、优先级、标签、Skill 关联和复制历史不变。
- 新旧应用来回切换时，旧应用保存主数据不会删除独立 Deadline 文件。
- 标题与目标日期必填；通知开启时明确时间必填，通知关闭时可以没有时间。
- 今天、未来 N 天、已到期 N 天在本地自然日边界正确，跨午夜后无需重启即可更新。
- 多个 Deadline 可独立完成、归档、恢复和经确认永久删除；首版没有自动永久清理。
- 重点项完成或归档后自动选择最近下一项，没有下一项时隐藏倒数。

### Menu bar

- 文字区左键复制原提示词；右侧日历图标左键打开面板；任意区域右键打开原生菜单。
- 日历图标有足够命中区和即时反馈；复制成功状态不会让图标消失。
- 右键菜单存在“打开 Deadline / 倒数日…”备用入口。
- 空间不足时保留 Deadline 和日历入口，先移除普通待办计数，再缩短提示词。
- 若单按钮分区在真实系统不稳定，只有规格中写明的安全降级可用，并记录证据与偏差。

### Panel and visual review

- 月份切换、今天、日期筛选、“全部”、四种列表状态和新增 / 编辑流程可用。
- 日期格只用简洁标记表示项目；右栏按已批准规则排序。
- 面板可拖动、可关闭、可再次唤起，并记住合理位置 / 尺寸；不会抢焦点、遗失到屏幕外或产生重复窗口。
- 浅色、深色、增强对比度、减少透明度和减少动态效果下内容清楚可读。
- 用户通过截图或现场运行明确验收整体信息密度、圆角、材质、间距、强调色和菜单栏命中感受。

### Notifications

- 多个开启通知的 Deadline 均可独立安排；重点项切换不影响其他请求。
- 到时在获得系统授权且未被系统模式抑制的情况下弹窗并播放系统声音；前台运行时也不静默丢失。
- 每项只通知一次；点击通知打开并定位对应 Deadline。
- 编辑时间正确重排；关闭通知、完成、归档和永久删除正确取消待触发请求。
- 权限拒绝或系统关闭声音时，界面显示真实状态，Deadline 与菜单栏倒数仍可使用。

### Regression and resource checks

- 原有提示词复制、右键菜单、待办、Skill、搜索、快速添加和设置行为通过回归检查。
- 空闲时没有每秒计时或日历轮询；采样 CPU 应接近现有空闲基线。
- 记录实现后应用包大小、RSS 和 `footprint`，与讨论阶段基线比较；明显偏离约 3–5 MB 包体和面板打开时约 10–30 MB 增量预算时必须说明原因。

## Implementation phases

### Phase 1 - Domain and reversible storage

- 实现独立 Deadline 模型、store、自然日计算、排序、状态和重点接续。
- 使用独立原子文件并完成旧数据兼容、损坏数据保留和 round-trip 测试。
- 不改变现有状态栏或通知权限。

Checkpoint: 运行模型 / 存储测试，证明旧主数据与新 Deadline 文件互不破坏。

### Phase 2 - First visible panel

- 实现双栏 Deadline 面板、月历、筛选、添加 / 编辑 / 完成 / 归档 / 恢复 / 确认删除。
- 接入独立 store，完成浅色 / 深色和基本可访问性检查。
- 生成真实运行截图，先让用户看到第一版整体样子；不得用静态模型自评代替运行观察。

Checkpoint: 用户可见截图或现场运行，记录视觉问题；未通过视觉检查前不部署。

#### Phase 2 visual correction checkpoint — 2026-08-21

用户查看首轮运行截图后明确反馈：当前成品感不足，执行主线不应继续用重复截图代替设计修正。以下内容属于已批准界面的质量澄清，不增加功能范围：

- 先停止截图循环，保留已有证据；完成一轮结构修正后，只提交三张可比较的运行证据：有真实列表内容的主面板、添加 / 编辑页、菜单栏入口与倒数状态。
- 修复星期标题全部显示为“周”的错误，并确保标题顺序与日历实际首日一致。
- 全部用户可见文案统一为中文；产品内部仍可使用 `Deadline` 作为领域名，界面统一使用“日历与提醒”“截止日”等同一套词汇。
- 只保留一个主要“添加截止日”入口，移除空状态下重复、争夺注意力的第二个入口。
- 玻璃材质只能有一个容器负责，避免面板工厂与 SwiftUI 内容重复叠加材质导致灰蒙；浅色、深色及非激活状态均须保持文字层级清楚。
- 窗口控制只能采用一套完整逻辑：若保留自定义关闭按钮，应隐藏全部系统交通灯；不得出现两个残留圆点和另一个关闭按钮并存。
- 右栏筛选采用单一选中状态；空状态应克制，不用大号标题占据主要视觉中心。
- 使用仅供验证、绝不写入用户数据的临时样例，至少覆盖今天、未来、已到期、已完成、通知开启和重点状态；不能只凭空页面判断列表密度与操作层级。
- 视觉验收以信息层级、交互位置、激活 / 非激活可读性和真实数据密度为准，不逐像素照搬参考软件，也不在结构未定时反复微调颜色和阴影。

本检查点未通过前，Phase 2 保持“待用户验收”，不得以构建成功或截图数量替代视觉完成。

### Phase 3 - Menu bar integration

- 加入尾随图标、文字 / 图标分区、Deadline 优先标题、午夜更新和右键备用入口。
- 在真实 macOS 26 菜单栏验证左键、右键、多显示器、空间不足和复制反馈。

Checkpoint: 记录实际点击测试和截图；若需要安全降级，先记录证据并向用户报告。

### Phase 4 - One-shot notifications

- 接入权限请求、一次性安排、重排、取消、前台呈现和点击路由。
- 验证拒绝权限和系统声音关闭时的降级。
