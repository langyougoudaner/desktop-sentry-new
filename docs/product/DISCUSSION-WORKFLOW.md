# Single-mainline collaboration

Desktop Sentry no longer uses separate product-discussion and execution roles.

For every new product idea, change, or bug report, the mainline first has one natural
discussion with the user and then stops. It may explain its understanding, offer its
own judgment, and ask only questions that could materially change the result. It must
not begin implementation during that first response.

After the user replies, the same mainline implements the agreed direction. A new pause
is needed only when implementation uncovers a materially different decision or safety
risk. The user may bypass the discussion by explicitly saying “直接做，不用先讨论”.

Routine work does not require a draft, specification, handoff document, or separate
discussion task. Existing product documents remain historical context. Create a durable
note only when the user asks for one or a high-risk decision needs a lasting record.
